# Strato performance investigation — implementation plan

Specification: user request of 28 October 2026; current master 9935f133.

Goal: remove demonstrated redundant CPU work while preserving Vulkan command,
resource, descriptor, fence and guest/host memory semantics. Do not claim that
these changes isolate PR #294 or improve Zelda FPS without a Moto G100 test.

Approach: audit existing hot paths, reproduce waste with actual production
methods, then make bounded independent changes. Reject unmeasured broad shader,
scheduler, barrier, alias or memory-policy rewrites. Preserve ARM64 DevRelease.

1. RenderPassCache: test equal owned/borrowed keys with absent/present resolve
   arrays; observe the current hash-contract failure. Encode absent resolve
   count as zero, preserving all Vulkan create infos and equality semantics.
   Compare Release-mode host lookup allocations/time; run framebuffer tests.
2. BufferManager: validate disjoint live-map invariant from all insertion and
   coalescing sites. Test exact result identity/order and page-table fast path,
   plus work bounds on tail/gap queries. Stop reverse overlap scan when a prior
   nonoverlapping end is reached. Do not change locking or coalescing behavior.
3. Review both changes independently, record measured results and limitations,
   recheck master, publish independent commits on a new Draft PR. One existing
   PR-opened Release workflow is sufficient; no merge or Actions polling.

Validation focus: mixed subpasses, optional resolve arrays, end-exclusive
buffer boundaries, gaps, multiple overlaps, fast-hit bypass and unchanged
resource lifetime. Full Android/device validation is separate from host tests.
