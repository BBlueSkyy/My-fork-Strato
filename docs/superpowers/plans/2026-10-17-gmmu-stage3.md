# GMMU follow-up — selector capacity and ordered physical aliases

Base: PR354 / wip/gmmu-stage1 at 8291e41c. Preserve earlier work; publish each
validated change. No changes to PR234/244/353 or merge; no Actions monitoring.

The SpongeBob log reaches ConstantBuffers::Bind from MacroInterpreter::Execute.
No macro-decoding fault is demonstrated. Master clipped buffers at the first
physical span; stage2 correctly made full buffer requests strict. Selectors still
requested their optional default 0x10000 capacity as mandatory, causing valid
mapped prefixes to fail at Bind. Keep strict general buffers; clip optional
selector capacity only, retain resident/sparse disjoint spans before a true
unmapped byte, and require the actual load extent (offset + bytes). Bound CPU
constant reads must not escape a clipped view into a larger physical backing.

Deferred safeguards remain intentional: a dense Vulkan image/buffer cannot model
missing-page or repeated-physical shader writes within one invocation. Native
sparse support alone does not prove matching Tegra/Vulkan residency granularity.
Do not remove those guards without a demonstrated correct runtime path.

A separate investigation of the attached-CB readback TODO found that a simple
submit/retry callback is unsafe: storage/transform-feedback writes are marked
GPU-dirty during preparation, before their commands exist. An unconditional retry
can repeat on speculative writes. Target readback completion and published-vs-
preparation writer authority must be distinguished before widening that path.

Repeated-span validation: failing-before/passing-after real-memfd regression for
ordered last-alias-wins CPU writes, partial physical overlaps, clean backing
replicas, sparse discard, CpuDirty deferral, alias-reader fences and retry-mode
preservation. Invalid/immutable/GpuDirty/pending-target-fence/GPU/CopyFrom cases
remain rejected before accounting or data mutation. Existing conditional tests
pass. Payloads retain the stable/nonoverlapping input requirement of Buffer::Write;
the repeated aggregate caller is the engine-owned constant-upload batch vector.

Final validation: host selector, GMMU, sparse/TIC mapping, disjoint-buffer,
conditional/query/DRAW_TEXTURE and pitch/BC regressions passed. Real Vulkan
(Lavapipe, synchronization validation) passed with zero validation errors.
ARM64 Linux ELF binaries under QEMU passed selector (six groups), GMMU (5000
updates / 25000 queries) and disjoint-buffer cache/authority/retry tests.
`python3 tests/run_arm64.py` repeats those suites after installing
`g++-aarch64-linux-gnu qemu-user libboost-dev`. ARM64 uses UBSan except vptr:
GCC13 type_info instrumentation recurses even in standalone make_shared /
shared_from_this under this QEMU runtime; native suites keep ASan/UBSan intact.
This is not Android or Turnip validation; no SpongeBob device run is claimed.
Await Moto G100 tests before removing remaining sparse/GPU-write safeguards.
