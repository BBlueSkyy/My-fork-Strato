## Final scope and cleanup

Removed `SoftwareKeyboardWindow` and every SWKBD-specific call that attempted to hide navigation. Removed the custom `onCreateDialog`/window-focus override introduced solely to reapply that request. DialogFragment now creates its normal default dialog again. Text-check alerts no longer modify system bars. Removed the three tests and shadow bookkeeping that existed only to validate experimental navigation requests.

The pre-existing EmulationActivity immersive setup is unchanged from master. The functional `show(ime())` requests on editing resume remain: they open the keyboard, not hide system bars. NO_EXTRACT_UI / NO_FULLSCREEN, inline transparency, non-touchable window behavior and text focus also retain the base implementation's behavior.

There is no SWKBD-triggered touch-control hiding, touch release or Activity-wide touch interception. `emu_activity.xml`, `onTouch`, physical key dispatch and generic-motion dispatch retain their master behavior. User-hidden controls are never forced visible by opening/closing the keyboard. A normal keyboard remains a modal dialog; inline retains its original touch pass-through.

The separate PiP helper remains because it fixes user visibility restoration and releases inputs owned by the disappearing touch view. It is invoked only by PiP callbacks, never by keyboard sessions. The initialization fix that prevents a disabled controller from being made visible is retained.

Historical follow-up/navigation comparison documents were consolidated here; their previous contents remain in Git history. No temporary production logging, instrumentation, polling, extra permissions or private APIs remain.

## Definitive functional corrections

| Area | Defect corrected and resulting behavior |
| --- | --- |
| Invalid-character flags | Kotlin precedence discarded the configured flag bit. Each getter now masks the intended shifted bit; restriction/download-code behavior is tested independently. |
| Unicode and composition | UTF-16 boundary mapping clips spans to the replacement slice, preserves supplementary characters and handles empty spans, removed characters and length truncation without invalid indexing. Existing byte/unit limits remain enforced. |
| Cursor bounds/state | Initial, restored and guest-provided selections are bounded against actual filtered Editable length. Pending/saved text and cursor survive view recreation and text-check retry. |
| Inline cursor replies | Cursor-only Android selection changes now reach JNI and generate UTF-16/UTF-8 MovedCursor or V2 replies. Programmatic guest updates refresh the observation baseline to avoid echoing cursor changes. |
| Session ownership | Frontend forwarding checks dialog identity as well as session ID. Stale/dismissed dialogs cannot submit through or unregister a replacement; restored visible dialogs register their current session without another JNI open call. |
| Back and IME transitions | Actual Back is handled before IME consumption, once, respecting disabled cancellation. IME inset/visibility changes by themselves do not cancel or submit an applet. Resume/retry explicitly requests the IME for an editing session. |
| Resource lifecycle | Binding, cursor observer, Back callback and owned text-check alert are released with the view/session. Text-check state is retained for resumed views; unexpected frontend loss unblocks a cancel-disabled native keyboard. |
| Touch preferences/PiP | SWKBD leaves controls/settings untouched. Disabled controls stay disabled at initialization; PiP restores the original VISIBLE/INVISIBLE/GONE state across repeated callbacks. |

## Protocol, integration and review result

Normal V0/V7/VB configuration sizes (`0x3E0`, `0x400`, `0x4C8`), output/text-check sizes (`0x7D8`, `0x7DC`), confirmation/cancellation and text-check transitions are preserved. Inline Calc sizes (`0x4A0`, `0x4C8`, `0x4E8`), FrontendOpened acknowledgement and the existing initialize/appear/hide/finalize state machine are preserved.

The inline reply helper remains in CMake and in host tests. Fixed text buffers stay `0x3EC` UTF-16 / `0x7D4` UTF-8 bytes; lengths/cursors use UTF-16 units in both encodings. ChangedString keeps its dictionary sentinels, MovedCursor uses length/cursor arguments, and V2 appends the expected zero flag. JNI accepts the added CursorMoved event; normal mode ignores it.

Native state/queue/session mutex ownership and asynchronous worker/UI dispatch are unchanged. Session registry callbacks retain their owner while dispatching outside the registry lock. No blocking UI/native wait or new shared mutable state was introduced by cleanup.

No additional functional defect was established in this final review. The final diff is limited to SWKBD correctness/lifecycle, the retained touch-preference/PiP fixes, integration and directed tests. Production changes from the navigation cleanup are confined to deleting its helper, custom focus wrapper and call sites.

**Integration assessment:** technically ready within the reviewed scope; no local correctness blocker was found and all directed checks below passed. The system navigation investigation is not an integration blocker. The PR remains Draft and has not been merged; ordinary CI/reviewer acceptance still applies.

## Remaining implementation limits

Custom dictionaries/prediction and complete Switch-specific language/layout behavior remain unimplemented. Layout is delegated to the Android IME; Separate/blur presentation is incomplete and the indirect display supplies a transparent image rather than rendering a complete Switch keyboard. No new gamepad text-navigation support or redesign of cross-thread ordering of simultaneously issued guest applet actions is included. These pre-existing limits are independent of the closed navigation investigation.

The earlier protocol comparison used the MIT-licensed Ryujinx implementation retained in Kenji-NX at `a6a641ada215837297e7170c91c6b4e8275574c6`, including SoftwareKeyboardApplet.cs, InlineResponses.cs and Calc/Appear/response structures, plus Eden's applet protocol. Agreement with those implementations is not hardware certification. No Eden code was transplanted into the MPL implementation.
