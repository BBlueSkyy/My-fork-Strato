## Confirmed defects and changes

1. **Controls remain visible and receive touch input.** The Activity never suppressed the controller, pause button or controller toggle during SWKBD. Inline deliberately uses `FLAG_NOT_TOUCHABLE`, passing touches to the Activity. One visibility snapshot now covers keyboard and picture-in-picture suppression, preserving VISIBLE/INVISIBLE/GONE across replacement, failure and close. Activity touch dispatch is consumed while a live frontend is registered; gamepad key and joystick dispatch remain unchanged.
2. **Held virtual inputs survive taking focus.** The button handler has no complete ACTION_CANCEL release path. The keyboard now explicitly releases the touch view's pressed/toggled buttons, active sticks and pending recenter animations, and clears guest touchscreen points when suppression starts. It does not reset all controller slots or all physical button/axis state.
3. **IME composition span crashes/corruption.** The filter indexed spans using unclipped source positions, had no end-boundary entry, and treated a supplementary character's final UTF-16 unit as another character. Clipped UTF-16 boundary mapping handles zero-length ranges, spans crossing the replacement slice, surrogate pairs and removed/truncated characters.
4. **Cursor outside filtered text.** Initial and guest-provided cursor bounds used the unfiltered input length. They now use actual Editable length; pending and saved cursor positions survive view recreation. Text-check retry preserves the cursor.
5. **Missing cursor-only inline replies.** `SetMovedCursorV2` was accepted and stored but never used. Cursor-only Android selection changes now generate the proper UTF-16/UTF-8 MovedCursor/V2 reply. The unchanged text-reply serialization was moved into a directly tested helper, with the moved-cursor variants added. Programmatic frontend updates update the observation baseline to avoid echoing them as user cursor movements.
6. **Stale Android windows and callbacks.** Text-check alerts were not owned/closed with their keyboard; view binding outlived the view; queued callbacks were checked only by numeric session ID, even though inline can reopen with the same ID. Alerts are owned and released, text-check/cursor state is saved, binding is cleared and Activity event forwarding checks dialog identity. Unexpected frontend loss unblocks even a cancel-disabled guest keyboard.
7. **Back hides only the IME in inline mode.** The focused transparent dialog could stay active after Back dismissed the IME. Window insets detect the visible-to-hidden IME transition while resumed and focused, then report cancellation (or request IME visibility when guest cancellation is disabled). A background pause or text-check alert is excluded from that transition. Resume explicitly requests the IME for an editing session.
8. **Disabled controls could be made visible during initialization.** Setting `isInvisible = false` after `isGone = true` overwrote GONE. Initial physical-controller visibility is now applied only when the touch controller is enabled.

9. **Invalid-character flags were ignored.** In each Kotlin getter, `(flags and 1u shl n)` groups as `(flags and 1u) shl n`, discarding the actual flag bit. The eight getters now mask with `(1u shl n)` explicitly. The failing restriction/download-code tests exposed the defect; the regression suite checks every configured flag independently.

## Protocol and concurrency review

- Normal V0/V7/VB argument sizes remain `0x3E0`, `0x400`, `0x4C8`; API-version selection and bounds-checked initial UTF-16 reads are preserved.
- Inline Calc sizes remain `0x4A0`, `0x4C8`, `0x4E8`, with their existing offsets/flags. The Initialize/Appear/Shown/Disappear/Hidden/Finalize handshake and FrontendOpened acknowledgement are preserved.
- Normal output remains `0x7D8`; text-check request remains `0x7DC`. Normal cancellation is distinct from submission and returns no accepted text.
- Inline fixed text buffers remain `0x3EC` UTF-16 and `0x7D4` UTF-8 bytes; lengths and cursors remain UTF-16 code units even in UTF-8 replies. ChangedString keeps its two `-1` dictionary positions. MovedCursor has only length/cursor; V2 appends a zero flag.
- Native mutexes protect normal/inline state, queue pop/push and session lookup. Registry dispatch takes a shared callback reference and releases its registry mutex before invoking it, preserving reentrant unregister. JNI strings and direct buffers remain copied/decoded before their local lifetime ends. The single frontend worker and UI queue remain asynchronous; no blocking UI/native wait was introduced.
- All map/visibility/window mutations remain on the UI thread. Replacement keeps suppression in place; callbacks from removed dialogs cannot remove or submit through their replacement.

## References and accuracy boundaries

Compared against the Ryujinx implementation retained in Kenji-NX at `a6a641ada215837297e7170c91c6b4e8275574c6`, specifically `SoftwareKeyboardApplet.cs`, `InlineResponses.cs`, Calc/Appear structures and inline response enums. Also inspected [Eden's applet protocol](https://github.com/eden-emulator/mirror/blob/master/src/core/hle/service/am/frontend/applet_software_keyboard.cpp) (content blob `fe07d7291220382464f047bf9a332d0445857e61`) and [Android frontend](https://github.com/eden-emulator/mirror/blob/master/src/android/app/src/main/java/org/yuzu/yuzu_emu/applets/keyboard/SoftwareKeyboard.kt) (blob `26e787f3771450e6458a0f26e08cf47edb0a0e1a`), retrieved 2026-11-24. The comparison establishes implementation agreement, not hardware certification. No Eden code was copied into the MPL implementation.

Existing limitations remain: custom dictionaries/prediction are not implemented, keyboard-specific Switch language/layout behavior is delegated to the Android IME, Separate/blur presentation is incomplete, and the indirect display returns a transparent image rather than rendering a complete Switch keyboard. Physical controller dispatch is preserved, not extended with new gamepad text-navigation support. The current changes do not redesign cross-thread ordering of simultaneously issued guest applet actions.

## Reproducible validation

- `bash tests/swkbd/run.sh`: production text/config/state/session/queue/indirect-layer helpers plus 30 inline wire-format cases (10 reply types × 3 cursor positions).
- Build the same C++ sources with `-fsanitize=address,undefined -fno-omit-frame-pointer` and run. In this managed host use `ASAN_OPTIONS=detect_leaks=0`: LeakSanitizer cannot run under its ptrace supervision. This is not a leak-test claim.
- `./gradlew -p tests/swkbd/android test --no-daemon`: isolated Robolectric API 29 tests using actual production filter/config/visibility code and real Android spans/views, without building native emulation. Covers clipped/empty spans, supplementary characters, restrictions, byte/unit limits, replacements, repeated keyboard opens and both PiP-close orders.
- PR Build runs the SWKBD tests before the normal ARM64 DevRelease build. Results, exact head and APK artifact are recorded in the PR description.

The isolated tests do not instantiate the full EmulationActivity/DialogFragment, real IME, native applet service or hardware gamepad. There is no attached Moto G100 or Switch hardware. APK compilation and these tests do not establish on-device behavior or FPS.

Local result: all 9 Robolectric tests and the native suite passed. ASan/UBSan passed with leak detection disabled as described above. These results cover helpers, not the complete Android applet lifecycle.
